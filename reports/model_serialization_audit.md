## 4. API Ingestion & Preprocessing Audit

### Schema Gap Identified and Resolved
Prior to Task 1.8, the preprocessing function `clean_and_prepare_data()` strictly required `Person ID` and composite `Blood Pressure` in `validate_columns()`, raising `ValueError` when receiving typical API payloads.

**Audit Corrections Applied to `ml/preprocess.py`**:
1. **Optional `Person ID` in Inference**: When `is_inference=True`, `Person ID` is no longer required. If provided by the client, it is safely dropped before inference.
2. **Dual Blood Pressure Ingestion**:
   - If compound `Blood Pressure` string (`"120/80"`) is provided, it is parsed into `BP_Systolic` (120.0) and `BP_Diastolic` (80.0).
   - If pre-split `BP_Systolic` and `BP_Diastolic` are provided as numbers, they are validated and passed directly to the `col_transformer`.
3. **BMI Normalization**: `"Normal Weight"` is automatically normalized to `"Normal"` during payload validation.
4. **Unknown Category Resilience**:
   - `OneHotEncoder(handle_unknown='ignore')` in the pipeline maps unseen occupations (e.g., `"Astronaut"`, `"Pilot"`) to all-zero one-hot vectors, avoiding runtime crashes.
